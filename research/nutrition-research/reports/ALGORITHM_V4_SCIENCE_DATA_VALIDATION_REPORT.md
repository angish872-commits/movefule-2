# MoveFuel Algorithm V4 — Science & Data Validation Report

**Date:** 2026-08-10  
**Scope:** Personal Target Engine + deterministic nutrition truth + calorie-estimation benchmark harness  
**Status:** Software/reference validation complete; end-to-end live photo-calorie accuracy remains an empirical gate.

## 1. Decision

MoveFuel now separates two questions:

1. **Personal Target Engine:** approximately how much energy/protein/macros should this adult user start with for Lose weight, Maintain weight, Gain muscle, or Improve performance?
2. **Meal Estimation Engine:** approximately how many grams/calories/nutrients are in the photographed meal?

They intentionally have different validation standards. A target equation can be reference-validated against the published equation. A camera estimate must be validated against independently weighed food.

## 2. Personal Target Engine V4

### Energy maintenance baseline

- Uses the 2023 National Academies EER equations.
- Age 19+ uses the adult sex/PAL equations.
- Age 18 uses the published adolescent 14–18.99 equations with the +20 kcal/day growth allowance.
- Overall activity category is authoritative; training frequency is only a fallback.
- The equation output is a starting estimate, not a measurement of an individual's actual expenditure.

### Goal behavior

| App goal | Initial energy behavior | Protein central | Protein review band | Recalibration |
|---|---:|---:|---:|---|
| Lose weight | EER − 250 kcal/day | 1.6 g/kg/day | 1.2–1.6 g/kg/day | Multi-week weight trend, user-confirmed |
| Maintain weight | EER | 1.4 g/kg/day | 1.2–1.6 g/kg/day | Multi-week weight trend, user-confirmed |
| Gain muscle | EER + 200 kcal/day | 1.6 g/kg/day | 1.2–1.6 g/kg/day | Multi-week weight trend, user-confirmed |
| Improve performance | EER | 1.6 g/kg/day | 1.2–1.6 g/kg/day | Multi-week weight trend, user-confirmed |

The −250/+200 kcal goal adjustments are MoveFuel product starting rules, not universal physiological truths. V4 therefore never treats them as permanent. After at least 7 valid weigh-ins spanning at least 14 days, the trend engine can propose a small 100-kcal adjustment; it still requires user confirmation.

### Macro/fiber behavior

- Fat starts at 30% of energy.
- Protein is weight-based first.
- Carbohydrate receives the remaining energy.
- Fiber uses 14 g per 1,000 kcal.
- The engine checks resulting adult macro energy shares against AMDR reference ranges (protein 10–35%, fat 20–35%, carbohydrate 45–65%) and adds a review warning rather than silently rewriting the user's target.

### Planning interval

The target engine retains a product-requested ±15% planning screen, but never makes the band narrower than the relevant published NASEM equation RMSE. This is deliberately labeled an engineering planning band, **not a formal 95% confidence interval**.

## 4. USDA / Nutrition Truth Readiness

MoveFuel keeps source identity and nutrient arithmetic separate from visual estimation.

- FoodData Central remains the primary U.S. nutrition source family.
- Per-100-g records are scaled deterministically by selected grams.
- Missing nutrients stay unknown instead of being converted to zero.
- Source ID, revision, food/preparation identity, and coverage remain available for audit.
- Branded/package values can outrank generic foods when the exact package is known.

A small five-food web-derived USDA-linked arithmetic fixture is included at:

`nutrition-research/benchmark/v4/web-usda-derived-spot-checks.json`

It covers banana, cooked white rice, roasted chicken breast, hard-boiled egg, and plain whole-milk yogurt. A backend test loads that fixture and confirms MoveFuel's deterministic calculator reproduces every expected calorie/protein result from `per-100-g × grams / 100`.

This fixture is only an arithmetic spot check. Production authority remains direct FoodData Central ingestion/API, never the secondary display sites used for the spot check.

## 5. Meal-Calorie ±15% Validation Policy

For photographed meals, MoveFuel V4 explicitly separates three metrics:

1. **Central-within-15% rate** — whether the central predicted calorie value is within ±15% of weighed ground truth.
2. **Displayed interval coverage** — whether the true calorie value falls inside the app's stated min/max range.
3. **Interval sharpness** — how wide that range is relative to ground truth.

This prevents a meaningless result such as `0–5,000 kcal` from scoring as “correct” merely because it contains the truth.

The current acceptance thresholds are provisional engineering gates, not medical/scientific guarantees:

- at least 100 independent samples,
- central-within-15% rate >= 80%,
- displayed interval coverage >= 90%,
- mean relative interval width <= 60%.

These numbers must be revisited after the first real held-out benchmark.

## 9. What is validated vs. what is not

### Validated now

- The production energy equations match an independent implementation of the published equations.
- All four MoveFuel goals have deterministic, conservative starting behavior.
- Protein behavior is versioned and bounded for general-wellness use.
- Macro calculations are deterministic and AMDR-aware.
- Nutrition calculations from known grams and known per-100-g source records are deterministic.
- The benchmark system can score ±15% central accuracy, range coverage, and range width.
- Real measured Nutrition5k ground truths are staged without leaking ground truth into prediction.

### Still requires empirical execution

- Live Gemini food identity on the held-out images.
- Production segmentation/depth model artifact execution on those images.
- End-to-end grams and calorie predictions for at least 100 independent held-out meals.
- Regional held-out meals (momo, dal bhat, curries, rice, roti, chow mein, liquids, fried foods, restaurant meals).
- Physical Samsung phone / Galaxy Watch acceptance.

Until those are run, MoveFuel must **not** claim that its single-photo calorie estimates achieve ±15% accuracy in the real world.

## 10. Reproducible continuation

Run the complete local validation:

```bash
./verify_algorithm_v4.sh
```

When unrestricted internet/provider access is available, run the USDA and Gemini smokes, populate direct USDA data, execute the image pipeline on the held-out Nutrition5k examples, write only the predictions to the provided prediction CSV, and score them with:

```bash
python3 -m movefuel_fdc.cli algorithm-v4-calorie --input <prediction.csv>
```

The scoring code intentionally requires both coverage and reasonable interval width.
