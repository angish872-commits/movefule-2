# MoveFuel-2 Canonical Algorithm Layer

This branch isolates algorithm work from the UI work.

## Canonical rules

1. One canonical owner per algorithm responsibility.
2. `UNKNOWN` is not zero.
3. Raw observations are preserved separately from derived decisions.
4. Every derived decision records algorithm/policy/formula versions and reason codes.
5. AI may extract evidence, rank bounded candidates, or explain a result; it is not the final authority for safety, grams, calories, macros, or canonical transactions.
6. Pain/illness safety gates are separate from ordinary soreness/recovery.
7. Camera, barcode, search, manual entry, saved foods, recipes, and YouTube imports converge into one food-resolution + nutrient pipeline.
8. Training knowledge is reference data; user-specific plans, readiness, progression, performed sets, and recovery decisions belong to MoveFuel runtime.
9. UI dashboards consume algorithm contracts and do not reimplement business formulas.
10. Historical decisions remain reproducible.

## Canonical engine families

- Core contracts and evidence
- Profile and targets
- Nutrition
- PortionWise
- Food resolution
- Barcode
- Recipe and YouTube import
- Meal planning
- Shopping and pantry
- Training
- Muscle recovery / soreness
- Calendar
- Today orchestration
- Progress
- Health and wearables
- Watch and sync
- AI evidence / explanations

The registry contains the 167-algorithm architecture and marks implementation authority for each item.
